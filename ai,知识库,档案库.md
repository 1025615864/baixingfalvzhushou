### 🔴 模块 A：知识库服务生产化（最高优先级）

当前知识库服务只有**只读的统计和列表 API**，完全不具备内容管理能力。

#### A1. 完整 CRUD API

```
当前:
├── GET  /stats          ✅ 统计
├── GET  /vector-info    ✅ 向量信息
├── GET  /list           ✅ 列表查询
└── GET  /categories     ✅ 分类列表

需要补全:
├── POST   /knowledge                      创建知识条目
├── GET    /knowledge/{id}                  获取详情
├── PUT    /knowledge/{id}                  更新知识条目
├── DELETE /knowledge/{id}                  删除知识条目
├── POST   /knowledge/batch-import          批量导入 (CSV/JSON)
├── GET    /knowledge/export                导出
├── POST   /knowledge/{id}/publish          发布（审核后上线）
├── POST   /knowledge/{id}/unpublish        下线
├── POST   /knowledge/search                全文搜索
│
├── POST   /categories                      创建分类
├── PUT    /categories/{id}                 更新分类
├── DELETE /categories/{id}                 删除分类
│
├── POST   /vector/rebuild                  重建向量索引
├── POST   /vector/sync/{id}               同步单条到向量库
├── GET    /vector/health                   向量库健康状态
```

#### A2. 知识条目生命周期

```
草稿 (draft)
  │
  ├── 运营编辑内容
  │
  ▼
待审核 (pending_review)
  │
  ├── 审核员检查法律准确性
  │
  ├── 通过 ─────────────────▶ 已发布 (published)
  │                              │
  │                              ├── 自动同步到向量库
  │                              │   (Kafka: knowledge.published)
  │                              │
  │                              ├── 编辑更新 → 更新向量索引
  │                              │   (Kafka: knowledge.updated)
  │                              │
  │                              └── 下线 → 删除向量索引
  │                                  (Kafka: knowledge.unpublished)
  │
  └── 拒绝 → 退回修改 (rejected)
                │
                └── 修改后重新提交 → pending_review
```

```python
# models/archive.py — 增强后
class LegalArchive(Base):
    __tablename__ = "legal_archive"
    
    id = Column(Integer, primary_key=True)
    title = Column(String, nullable=False)       # 案例标题
    content = Column(Text, nullable=False)        # 案例全文
    category_id = Column(Integer, ForeignKey("archive_categories.id"))
    
    # 案例特有字段
    case_number = Column(String)                  # 案号 如"(2024)京01民终123号"
    court_name = Column(String)                   # 审理法院
    court_level = Column(String)                  # 法院级别 基层/中级/高级/最高
    judge_date = Column(Date)                     # 裁判日期
    case_type = Column(String)                    # 案件类型 民事/刑事/行政
    cause_of_action = Column(String)              # 案由
    judgment_result = Column(String)              # 判决结果摘要
    key_points = Column(Text)                     # 裁判要旨
    applicable_laws = Column(ARRAY(String))       # 适用法条
    
    # 来源
    source = Column(String)                       # 来源：裁判文书网/律师提交
    source_url = Column(String)                   # 原始链接
    is_guiding_case = Column(Boolean, default=False)  # 是否指导性案例
    
    # 生命周期 (同知识库)
    status = Column(String, default="draft")
    version = Column(Integer, default=1)
    vector_indexed = Column(Boolean, default=False)
    
    # 审核 + 元信息
    reviewed_by = Column(Integer)
    created_by = Column(Integer)
    created_at = Column(DateTime)
    updated_at = Column(DateTime)
```

### 🟠 模块 D：向量索引同步机制

**这是三个服务协作的核心问题。**

```
当前问题:

Knowledge Service        Archive Service          AI Service
┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│ PG: 法律知识  │        │ PG: 案例数据  │        │              │
│ Chroma: 向量  │        │ Chroma: 向量  │        │ Chroma: 向量  │
│              │        │              │        │ (谁的数据？)  │
│  各自独立     │        │  各自独立     │        │  各自独立     │
│  互不知道     │        │  互不知道     │        │  互不知道     │
└──────────────┘        └──────────────┘        └──────────────┘

问题1: 知识库新增一条法律 → AI Service 的 Chroma 不知道
问题2: 案例库更新一个案例 → AI Service 的 Chroma 还是旧数据
问题3: 三份 Chroma 数据可能完全不一致
```

**解决方案：Kafka 事件驱动 + 单一数据源**

```
目标:

Knowledge Service              Archive Service
┌────────────────────┐        ┌────────────────────┐
│ PG: 法律知识 (源头)  │        │ PG: 案例数据 (源头)  │
│ Chroma: 本地向量    │        │ Chroma: 本地向量    │
│                    │        │                    │
│ 写入时:             │        │ 写入时:             │
│ 1. 写入 PG         │        │ 1. 写入 PG         │
│ 2. 更新本地 Chroma  │        │ 2. 更新本地 Chroma  │
│ 3. 发布 Kafka 事件  │        │ 3. 发布 Kafka 事件  │
└────────┬───────────┘        └────────┬───────────┘
         │                              │
         ▼                              ▼
┌─────────────────────────────────────────────────────┐
│                    Kafka                              │
│                                                     │
│  knowledge.published  →  AI Service 消费 → 更新向量  │
│  knowledge.updated    →  AI Service 消费 → 更新向量  │
│  knowledge.deleted    →  AI Service 消费 → 删除向量  │
│  archive.published    →  AI Service 消费 → 更新向量  │
│  archive.updated      →  AI Service 消费 → 更新向量  │
│  archive.deleted      →  AI Service 消费 → 删除向量  │
└─────────────────────────────────────────────────────┘
         │
         ▼
AI Service
┌────────────────────────────────────────────┐
│  Kafka Consumer:                           │
│  ├── 收到 knowledge.published              │
│  │   → 生成 embedding                     │
│  │   → 写入 chroma_knowledge              │
│  │                                        │
│  ├── 收到 archive.published               │
│  │   → 生成 embedding                     │
│  │   → 写入 chroma_archive               │
│  │                                        │
│  RAG 检索:                                │
│  ├── chroma_knowledge (本地, 始终最新)      │
│  ├── chroma_archive (本地, 始终最新)        │
│  └── 不再需要 Backend RAG Fallback         │
└────────────────────────────────────────────┘
```
