### 🔴 模块一：身份认证修复（P0 致命）

**当前致命缺陷**：`user_id` 由前端直接传入，任何人可以伪造任何用户身份发帖、删帖、点赞。

**修复方案**：两级认证体系

```
方案A (推荐): APISIX网关解析JWT → 注入 X-User-ID Header → 社区服务信任网关
方案B (备选): 社区服务自己调用 User Service 验证 Token
```

**目标认证流程**：
```
Frontend                 APISIX Gateway              Community Service
   │                          │                            │
   │  Authorization:          │                            │
   │  Bearer eyJhbG...        │                            │
   ├─────────────────────────▶│                            │
   │                          │  JWT验证                   │
   │                          │  提取 user_id, role        │
   │                          │                            │
   │                          │  X-User-ID: 12345          │
   │                          │  X-User-Role: user         │
   │                          ├───────────────────────────▶│
   │                          │                            │
   │                          │                  从Header取user_id
   │                          │                  不再从Body接收
   │                          │                            │
```

**核心代码设计**：

```python
# middleware/auth.py
class AuthMiddleware:
    """
    从APISIX注入的Header中提取用户信息
    如果Header不存在 → 调用 User Service 验证 Token (Fallback)
    """
    
    async def get_current_user(self, request: Request) -> AuthUser:
        # 优先从网关注入的Header获取（性能最优）
        user_id = request.headers.get("X-User-ID")
        user_role = request.headers.get("X-User-Role")
        
        if user_id:
            return AuthUser(id=int(user_id), role=user_role)
        
        # Fallback: 自行验证Token
        token = request.headers.get("Authorization", "").replace("Bearer ", "")
        if not token:
            raise HTTPException(401, "未登录")
        
        user_info = await self.user_client.verify_token(token)
        return AuthUser(id=user_info["id"], role=user_info["role"])


# routers/post.py — 修复后
@router.post("/posts")
async def create_post(
    request: PostCreateRequest,          # ← 不再包含 user_id
    current_user: AuthUser = Depends(get_current_user),  # ← 从Token获取
    post_service: PostService = Depends()
):
    return await post_service.create_post(
        user_id=current_user.id,         # ← 可信的 user_id
        title=request.title,
        content=request.content,
        category=request.category
    )
```

**同时需要实现的权限控制**：

| 操作 | 权限规则 |
|------|---------|
| 创建帖子 | 任何已登录用户 |
| 编辑帖子 | 仅作者本人 |
| 删除帖子 | 作者本人 OR 管理员 |
| 删除评论 | 评论作者 OR 帖子作者 OR 管理员 |
| 置顶/加精 | 仅管理员 |
| 封禁用户 | 仅管理员 |

### 🔴 模块二：Service 层引入（P0 架构）

**当前问题**：路由直接操作数据库（Fat Router），业务逻辑散落在路由中，无法测试、无法复用。

**目标**：Router 只做**参数校验 + 调用 Service**，所有业务逻辑下沉到 Service 层。

```
当前 (Fat Router):
Router → 直接SQL查询 → 直接返回

目标 (Thin Router + Service):
Router → Service → Repository(可选) → DB
            │
            ├── 权限检查
            ├── 业务规则校验
            ├── 内容审核
            ├── 事件发布
            └── 缓存更新
```

**PostService 核心设计**：

```python
# services/post_service.py
class PostService:
    def __init__(self, db: AsyncSession, user_client, event_bus, 
                 moderation_service, cache):
        self.db = db
        self.user_client = user_client
        self.event_bus = event_bus
        self.moderation = moderation_service
        self.cache = cache
    
    async def create_post(self, user_id: int, title: str, 
                          content: str, category: str) -> Post:
        """
        创建帖子的完整业务流程：
        1. 内容审核（敏感词 + AI）
        2. 获取用户信息（昵称、头像、律师标识）
        3. 创建帖子记录
        4. 发布 Kafka 事件
        5. 清除相关缓存
        """
        # Step 1: 内容审核
        moderation_result = await self.moderation.check_content(title + content)
        if moderation_result.blocked:
            raise ContentBlockedException(moderation_result.reason)
        
        # Step 2: 获取用户信息
        user_info = await self.user_client.get_user_info(user_id)
        
        # Step 3: 创建帖子
        post = Post(
            user_id=user_id,
            author_name=user_info.nickname,
            author_avatar=user_info.avatar,
            is_lawyer=user_info.is_lawyer,      # ← 律师认证标识
            title=title,
            content=content,
            category=category,
            status="published" if not moderation_result.needs_review 
                   else "pending_review"
        )
        self.db.add(post)
        await self.db.commit()
        
        # Step 4: 发布事件
        await self.event_bus.publish(CommunityEvent(
            event_type="community.post.created",
            data={"post_id": post.id, "user_id": user_id, "category": category}
        ))
        
        # Step 5: 清除缓存
        await self.cache.invalidate_list_cache(category)
        
        return post
    
    async def delete_post(self, post_id: int, current_user: AuthUser):
        """删除帖子 — 包含权限检查"""
        post = await self._get_post_or_404(post_id)
        
        # 权限检查：作者本人 或 管理员
        if post.user_id != current_user.id and current_user.role != "admin":
            raise HTTPException(403, "无权删除此帖子")
        
        post.is_deleted = True  # 软删除
        await self.db.commit()
        
        await self.event_bus.publish(CommunityEvent(
            event_type="community.post.deleted",
            data={"post_id": post_id, "deleted_by": current_user.id}
        ))
```

**关键设计决策**：

| 决策 | 方案 | 理由 |
|------|------|------|
| 评论嵌套 | `parent_id` + `reply_to_user_id` | 支持无限嵌套但前端只展示2层 |
| 楼层编号 | `floor_number` 自增 | 法律社区习惯看楼层 |
| 计数器 | 冗余在 Post 表 | 避免 COUNT 查询，性能关键 |
| 用户信息 | 冗余 `author_name` | 避免每次查询调用 User Service |
| 软删除 | `is_deleted` + `deleted_at` | 法律内容需要审计留痕 |
| 热度分 | `hot_score` 定时计算 | 避免实时计算拖慢查询 |

### 🟠 模块四：内容审核系统（P1 — 法律平台必须）

内容审核架构应遵循漏斗模式：快速廉价的过滤器捕获明显违规，更昂贵的模型分析模糊内容，人工审核处理最难的案例。

建议采用混合审核框架，结合自动化算法和人工监督，以平衡效率与上下文理解。

**三级审核流水线**：

```
用户提交内容
      │
      ▼
┌──────────────────────────────────────────────────────────┐
│  Level 1: 本地敏感词过滤 (< 5ms)                          │
│                                                          │
│  • 法律行业敏感词库                                       │
│  • 政治敏感词                                             │
│  • 广告/诈骗关键词                                        │
│  • 联系方式提取（防私下交易）                               │
│                                                          │
│  命中？──YES──▶ 直接拦截，返回提示                         │
│    │                                                     │
│   NO                                                     │
│    ▼                                                     │
├──────────────────────────────────────────────────────────┤
│  Level 2: AI 内容分析 (< 500ms)                           │
│                                                          │
│  调用 AI Service 或 LLM：                                 │
│  • 判断是否包含法律误导性内容                              │

# services/moderation_service.py
class ModerationService:
    """三级内容审核"""
    
    async def check_content(self, content: str) -> ModerationResult:
        # Level 1: 敏感词（同步，极快）
        word_result = self.sensitive_filter.check(content)
        if word_result.has_violation:
            return ModerationResult(
                blocked=True,
                reason=f"包含敏感词: {word_result.matched_words}",
                level="keyword"
            )
        
        # Level 2: AI分析（异步，可选降级）
        try:
            ai_result = await asyncio.wait_for(
                self.ai_client.analyze_content(content),
                timeout=2.0  # 2秒超时
            )
            if ai_result.confidence > 0.9:
                return ModerationResult(blocked=True, reason=ai_result.reason)
            elif ai_result.confidence > 0.5:
                return ModerationResult(blocked=False, needs_review=True)
        except asyncio.TimeoutError:
            # AI服务不可用时降级：仅依赖 Level 1
            pass
        
        return ModerationResult(blocked=False, needs_review=False)
```

### 🟡 模块六：热门内容系统（P2）

**热度评分算法（Hacker News 变体，适配法律社区）**：

```python
# utils/scoring.py
import math
from datetime import datetime, timedelta

def calculate_hot_score(
    likes: int,
    comments: int, 
    views: int,
    favorites: int,
    is_lawyer_post: bool,
    created_at: datetime
) -> float:
    """
    法律社区热度算法
    
    特点：
    - 律师发帖权重更高（专业内容优先）
    - 评论权重 > 点赞权重（鼓励深度讨论）
    - 时间衰减因子（12小时半衰期）
    """
    # 互动分
    engagement = (
        likes * 1.0 +
        comments * 3.0 +      # 评论权重最高（法律讨论价值高）
        favorites * 2.0 +
        math.log10(max(views, 1)) * 0.5
    )
    
    # 律师加成
    if is_lawyer_post:
        engagement *= 1.5
    
    # 时间衰减（12小时半衰期）
    hours_since_post = (datetime.utcnow() - created_at).total_seconds() / 3600
    time_decay = 1.0 / (1.0 + (hours_since_post / 12.0) ** 1.5)
    
    return round(engagement * time_decay, 4)
```
